# Replace the conversation profile icon and add username settings

## Description
Replaces the blue `R` header icon in conversation screens with a default profile icon and a `You` label. Tapping the icon opens a compact submenu for account actions, beginning with changing the signed-in user's username. The menu is designed to accommodate additional options later. Out of scope: custom profile pictures, changing another user's username, deleting an account, and changing the household name.

## Specs
- Conversation headers in the Chat and Chores screens:
  - Do not display the existing blue `R` icon.
  - Display a neutral, default profile picture with the text `You` underneath it.
  - Keep the existing household title, invite code, and member controls functioning and visually separated from the profile control.
- Tapping the profile picture or `You` label opens a submenu anchored near the profile control.
- The submenu contains a `Change username` option.
- The submenu is extensible: its implementation and layout must allow additional account options to be added without redesigning the menu.
- Choosing `Change username` opens an input for the signed-in user's new username.
  - The input is prefilled with the current username.
  - Selecting or confirming the change submits the new username.
  - The username must be trimmed and must contain at least 1 character and no more than 50 characters.
  - The username is compared case-insensitively when determining whether it is the same as or conflicts with an existing account.
  - A successful change closes the submenu and updates the signed-in session and visible username state in the members menu.
- A username change is not allowed to sign a user out or switch accounts.
- Existing real and fake-data API behavior must provide equivalent username-change operations.
- Error states:
  - Invalid or over-50-character usernames display a clear validation error.
  - An already-taken username returns a conflict or displays an equivalent clear error.
  - API, network, and session-expiration errors use the existing app error-handling patterns and do not partially update the username.
- The profile control and submenu remain usable while the conversation is loading or after an API error.
- Closing behavior:
  - Tapping outside the submenu closes it.
  - Tapping the profile control again closes it.
  - Opening `Change username` replaces or closes the main submenu and presents the username form.
  - Returning from the username form restores the main submenu or closes the menu consistently, according to the app's existing modal/navigation pattern.

## Requirements
- Preserve the authenticated account and session token; username changes may update account identity data but must not create or switch sessions.
- Use a single, authenticated API operation for persisted username changes rather than a caller-supplied account or client-only state.
- Apply the change to real database-backed account data and to the fake-data API.
- Update references displayed by the active session, including conversation messages and sender labels, after a successful rename.
- Use case-insensitive matching for username uniqueness and existing-account checks.
- Preserve existing behavior for household membership, invitations, message sending, and account sign-in.
- Do not change the blue `R` on authentication or join screens; this task applies only to conversation headers.
- Existing tests must keep passing. Add focused mocked-API or mocked-`pg` tests for successful and rejected username changes.

## Acceptance criteria
1. Neither Chat nor Chores conversation headers displays the blue `R`.
2. Both conversation headers show a default profile picture and `You` underneath.
3. Tapping the profile control opens a submenu with `Change username`; tapping it again or tapping outside closes it.
4. The submenu can contain future options without requiring a structural redesign.
5. The username form is prefilled, validates 1-50 characters after trimming, and rejects a taken username.
6. A valid username change is persisted and reflected throughout the signed-in app without changing accounts or logging out.
7. Invalid input or API errors leave the original username unchanged and display an appropriate message.
8. No behavior outside the conversation profile control is changed, including household and authentication screen branding.
