# Show household info with invite code, members, rename, leave and log out

## Description
Serves US-3 (manage my household) through sprint plan Task 3.13. This slice adds a Household info screen, opened from the board, that shows the household's invite code with Copy and Share buttons, lists its members with the owner marked, lets the owner rename the household, and lets any member leave or log out. It also adds the owner-only rename endpoint the screen needs. Out of scope: removing another member, transferring ownership by hand, changing the invite code, and deleting the household. Leaving uses the existing `DELETE /conversations/:inviteCode/members` route unchanged, including how it hands ownership to the longest-standing member.

## Specs
- `PATCH /conversations/:inviteCode` with `Authorization: Bearer <session token>` and body `{ "name": "Beach House" }`:
  - If the caller is the household's owner, the name is trimmed and saved, and the response is HTTP 200 with `{ "conversation": { "inviteCode": "<code>", "name": "Beach House" } }`.
  - A body without a string `name` returns 400 and `{ "error": "name must be a string." }`.
  - A name that is empty after trimming, or longer than 80 characters, returns 400 and `{ "error": "name must be between 1 and 80 characters." }`. Exactly 80 characters is accepted.
  - A member who is not the owner gets 403 and `{ "error": "Only the owner can rename this household." }`, and the name does not change.
  - A signed-in user who is not in the household also gets 403 with the same error.
  - An unknown invite code returns 404 and `{ "error": "Conversation not found." }`.
  - A missing or invalid bearer token returns 401.
- `sortMembers(members)` in `frontend/src/utils/members.ts` returns a new array with the owner first, then everyone else by username, ignoring letter case. It does not change the array it is given.
- `initial(username)` in the same file returns the first non-space character in upper case, or `?` for an empty or blank name.
- `frontend/src/screens/HouseholdInfoScreen.tsx`:
  - Shows the household name, the invite code, a **Copy code** button that copies the code with `expo-clipboard` and shows **Copied!** for 2 seconds, and a **Share** button that opens the share sheet with the message `Join <name> on Roomie with invite code <code>`. It falls back to copying when there is no share sheet.
  - Lists members from `GET /conversations/:inviteCode/users` in `sortMembers` order, with an **Owner** tag on the owner.
  - Shows **Rename** only to the owner. Saving an empty name shows "Name can’t be empty" without calling the server.
  - **Leave household** asks for confirmation, then calls `leaveConversation`, then returns to the create/join screen.
  - **Log out** signs out and returns to sign in.

## Requirements
- Rename is owner-only, and the check happens on the server, not just by hiding the button.
- The 80-character limit is shared through `HOUSEHOLD_NAME_MAX_LENGTH` in `frontend/src/types/messaging.ts` and matches the server.
- Use the existing `authenticated` helper and the existing leave route. No new tables or migrations.
- Use `expo-clipboard` and React Native's `Share`. No other new frontend dependencies.
- Existing tests in `tests/` must keep passing. New tests use a mocked `pg` pool and need no live database.

## Acceptance criteria
1. The owner can rename the household and gets HTTP 200 with the trimmed name.
2. A non-owner member, or a user outside the household, gets HTTP 403 from the rename endpoint, and the name is not changed.
3. A rename to an empty name, a whitespace-only name, or a name over 80 characters gets HTTP 400. An 80-character name is accepted.
4. Renaming with an unknown invite code gets HTTP 404.
5. Renaming without a valid bearer token gets HTTP 401.
6. `sortMembers` puts the owner first and the rest in case-insensitive name order, without changing its input.
7. `initial` returns the upper-case first letter of a username, and `?` for a blank one.
