# Choose which roommate a new chore list is for

## Description
Serves US-3 (keep household chores organized), covering the "assign to roommates" half of sprint plan Task 3.2 that the Chores tab does not offer yet. Today the New list form can only create a list for **Me** or the **Whole house**. This slice lets the person creating a list pick any roommate in the household, and the list then shows that roommate's name to everyone. Out of scope: reassigning an existing list, assigning single chores, notifications about an assignment, and any change to the server, which already accepts an `assignee`.

## Specs
- `assigneeChoices(members, username)` in `frontend/src/utils/chores.ts` returns the choices for the New list form as an array of `{ key: string, label: string, assignee: string | null }`:
  - First **Me**: `{ key: 'me', label: 'Me', assignee: <username> }`.
  - Then one choice per other member, sorted by username ignoring letter case: `{ key: 'user:<username>', label: <username>, assignee: <username> }`.
  - Last **Whole house**: `{ key: 'house', label: 'Whole house', assignee: null }`.
  - `members` is a `HouseholdMember[]` (`{ username, role }`). The signed-in user is matched ignoring letter case and is never repeated as a roommate choice. The array passed in is not changed.
- `assigneeLabel(list, username)` in the same file (moved out of `ChoresScreen.tsx`) returns the text of a list's badge: `'Whole house'` when `list.assignee` is `null`, `'You'` when it equals `username` ignoring letter case, otherwise the assignee's username.
- The existing `createChoreList(token, inviteCode, { title?, assignee? })` in `frontend/src/services/mockApi.ts` (fake-data mode) behaves like the real route `POST /conversations/:inviteCode/chores`:
  - A roommate's username, in any letter case, saves the list with that roommate as `assignee`, spelled the way the roommate's account spells it. With no title given, the title is `<assignee>'s chores`.
  - A username that is not a member of the household rejects with a `MessagingError` whose `code` is `INVALID_INPUT` and whose message is `assignee is not a member of this conversation.`. No list is created.
  - `getChoreLists(token, inviteCode)` called by any member returns that list with the same `assignee`.
- `frontend/src/screens/ChoresScreen.tsx` New list form: loads the members with `getMembers(token, inviteCode)` on mount and again when the list-name box gets focus. It shows one chip per `assigneeChoices` entry with **Me** selected first, and **Create list** passes the selected choice's `assignee` to `createChoreList`. If the members cannot be loaded, the form still offers **Me** and **Whole house**.

## Requirements
- No server, database or API changes, and no new dependencies.
- Use the existing `getMembers` and `createChoreList`; the list-name box and the check-off and delete behavior are unchanged.
- `frontend/src/utils/chores.ts` and `frontend/src/services/mockApi.ts` use `import type` for type-only imports, so Node's type stripping can load them in tests.
- Existing tests in `tests/` must keep passing. New tests need no database or network.

## Acceptance criteria
1. `assigneeChoices` lists **Me** first, then the other roommates in case-insensitive username order, then **Whole house** last.
2. The signed-in user appears only once, as **Me**, even when `members` contains their name in a different letter case.
3. With no other members `assigneeChoices` returns just **Me** and **Whole house**, and it does not change the array it is given.
4. Creating a list for a roommate saves it with that roommate as `assignee`, in the roommate's own spelling, and the default title `<name>'s chores`.
5. The roommate, and every other member, sees that list with the same `assignee` when they load the chore lists.
6. Creating a list for a username who is not in the household is rejected with `INVALID_INPUT`, and no list is created.
7. `assigneeLabel` returns `'You'` for the signed-in user's own list (ignoring letter case), the roommate's username for someone else's list, and `'Whole house'` when the list has no assignee.
